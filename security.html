Security

How we keep keys, servers and software safe, and how to tell us about a problem.

Report a problem bn@brilliantnodes.com

Keys

  • Owner and operator keys are kept apart. A validator’s operator key lives on its server. The owner key, which controls stake and settings, never does.
  • Recovery phrases never appear on a screen. They are written straight to locked files, never printed or logged, and copied to encrypted offline storage.
  • No secret goes into code or chat. Keys, passwords and tokens are never committed to a code repository, pasted into a form or shared in a message.
  • Server addresses stay private. Our public status page checks our nodes without showing where they are.

Servers

  • Validators run on their own servers, away from the machines that hold our automation and accounts.
  • Every node has a watchdog. A stuck process is restarted, and we are alerted only when something is definitely wrong, so real alerts are never lost in noise.
  • No change overwrites a working setup. Each change goes in as a new configuration file and the previous one is kept, so any change can be undone.
  • Rewards are checked every hour against the wallets they should reach.

Software

  • Pinned and hash-checked. Every program we run is a fixed version, checked against its published SHA-256 hash before it starts. We never install an unchecked “latest”.
  • Tested before it reaches our machines. A new version is rolled out only after we have tested it.
  • Outside programs run in isolation, in separate environments away from our own systems.
  • We read every release. We follow the releases of each network we serve and read the notes before every upgrade.

Our contracts and apps

  • Public code. Every contract and app on our site is open on GitHub.
  • Tested, then deliberately broken. Each contract has its own test suite, and we break it on purpose in many ways to prove the tests catch every change. Independent reviews come before we publish.
  • Limits written down. Each README lists what the contract does not protect against.
  • Test tokens and fictional names only. Our demos hold no real money and name no real company.

Report a problem

If you find a weakness in our site, our apps, our contracts or our nodes, please email bn@brilliantnodes.com. Our security.txt gives the same address.

  1. Tell us what you found, where, and how to reproduce it.
  2. Use only test accounts and test tokens, and access no more than you need to show the problem.
  3. Give us reasonable time to fix it before you publish anything.

We will confirm that your report arrived, keep you informed while we fix it, and thank you publicly if you would like that.
