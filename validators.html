How we run a validator

  • Our own servers. We run every node ourselves, on dedicated servers, away from the machines that hold our automation and accounts.
  • Spread across regions and providers. Our servers are in Chicago, São Paulo, Frankfurt, Prague, Johannesburg, Singapore and Melbourne, with several hosting providers, so a network stays stable if one region or provider has trouble.
  • Owner and operator keys kept apart. The operator key lives on the validator’s server. The owner key, which controls stake and settings, never does, and recovery phrases are kept offline.
  • Pinned, hash-checked software. Every program is a fixed version, checked against its published hash and tested before it reaches a validator. We read the release notes before every upgrade.
  • Monitoring and watchdogs. Every node has its own watchdog. A stuck process is restarted, and we are alerted when something is wrong.
  • Reward checks. Every hour we check that rewards reached the wallet they were meant for.

More detail on our security page.

Launch day

The first hours of a new network matter most. We bring up seed and hub nodes in three regions before the start, and rented machines across several providers, with spares. We have run more than 100 machines at once, in more than 20 countries.

  1. The day before: a full dress rehearsal, every step run end to end on test machines.
  2. 3 hours before: our hub and seed nodes are up in three regions, so no machine waits for a chain download.
  3. 2 hours before: machines rented across several providers, set up, checked and ready 30 minutes before the start.
  4. The last 3 hours: we check the project’s releases every five minutes and apply any change at once.
  5. 10 minutes after: the first check that rewards reach the right wallets, then the same check every hour.
